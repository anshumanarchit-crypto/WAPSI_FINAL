### Safety Boundary Enforcement

1. **Benchmark Distinction:** None of the model artifacts (`v1.0.0`, `v1.1.0`, `v1.2.0-dml`) are certified as trained on live merchant transaction history. Their manifest status is strictly locked as `BENCHMARK_VALIDATED_AWAITING_PRODUCTION_LOGS`.
2. **Readiness Exposure:** Both the API route (`POST /api/v1/causal/decision`) and the core supervisor (`DeterministicDecisionSupervisor`) explicitly return `model_readiness_status` and `deployment_mode` in every response payload and immutable decision snapshot.
3. **No Autonomous Dispatch:** In `ADVISORY_HUMAN_REVIEW` mode, benchmark-trained models are restricted from autonomously executing any customer-contacting intervention (`WHATSAPP_ONE_CLICK_LINK`, `SMS_FALLBACK_LINK`, `CALL_ASSIST_IVR`, `BNPL_ALTERNATIVE_OFFER`, `MERCHANT_DISCOUNT_NUDGE`).
4. **Approval Requirement:** Any candidate customer intervention recommended by model weights requires explicit operator pre-approval (`is_pre_approved_by_operator: true`). When pre-approval is absent, the decision supervisor sets `requires_human_approval: true`, marks `execution_status: "PENDING_APPROVAL"`, and sets `authorized_action: "NO_ACTION"`.

## 3. Conformal Calibration Audit

The empirical coverage of the split-conformal calibration pipeline was audited against the held-out test split ($N = 7,500$):

### Empirical Results vs. Nominal 90.0% Target

| Action Name | Test Cohort Size ($N$) | Realized Empirical Coverage | Nominal Target | Coverage Gap | Verdict |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **`voice_call`** | 627 | 99.46% | 90.0% | +9.46% | Conservatively Overcovered |
| **`email`** | 638 | 94.12% | 90.0% | +4.12% | Target Met |
| **`whatsapp_nudge`** | 2,462 | 87.94% | 90.0% | -2.06% | Minor Deficit |
| **`retry_only`** | 2,525 | 86.48% | 90.0% | -3.52% | Minor Deficit |
| **`no_action`** | 620 | 73.82% | 90.0% | -16.18% | Significant Deficit |
| **`incentive_link`** | 628 | 72.15% | 90.0% | -17.85% | Significant Deficit |
| **Overall Pooled** | **7,500** | **86.73%** | **90.0%** | **-3.27%** | Target Not Met |

### Root Cause Analysis

1. **Heteroskedastic Residual Variance Across Arms:** The global calibration threshold was calculated by pooling non-conformity residuals across all treatment arms. However, residual error variance is heterogeneous across arms:
   - For `no_action`, validation quantile was $q = 0.0551$, whereas the 90th percentile error on the test set was $0.0780$.
   - For `incentive_link`, validation quantile was $q = 0.1139$, whereas the 90th percentile error on the test set was $0.1582$.
2. **Finite-Sample Tail Discrepancy:** The smaller treatment arms ($N \approx 620$) exhibit higher tail variance in extreme payment failure scenarios (e.g. repeated technical timeouts vs. deliberate buyer abandonment).
3. **Honest Reporting Guarantee:** The calibration pipeline in `src/conformal_gate.py` evaluates realized empirical coverage honestly and sets:
   ```json
   {
     "nominal_target": 0.90,
     "empirical_coverage": 0.8673,
     "coverage_guarantee_met": false
   }
   ```
   No calibration set manipulation, post-hoc threshold tuning, or relabeling of the nominal target was performed. The models are reported honestly as failing the nominal 90% coverage target on `no_action` and `incentive_link`.

## 4. Decision Authorization Audit

The end-to-end decision authorization pipeline was inspected across `POST /api/v1/causal/decision`, `DeterministicDecisionSupervisor`, and execution paths.

```
+-------------------------------------------------------------------------------+
|                       Incoming Request: Case & Candidate                      |
+-------------------------------------------------------------------------------+
                                      |
                                      v
+-------------------------------------------------------------------------------+
| Gate 1: Deterministic Policy Engine                                            |
| - DND Hours Check (21:00 - 09:00 IST)                                         |
| - Channel Cooling Windows (WhatsApp: 4h, SMS: 6h, Call: 24h)                  |
| - Max Frequency Check (<= 3 touches / 24h)                                    |
| - Merchant Concession Cap (<= 15% discount)                                   |
+-------------------------------------------------------------------------------+
                                      | Passed
                                      v
+-------------------------------------------------------------------------------+
| Gate 2: Net Expected Value (NEV) Gate                                         |
| - NEV = P(recovery) * amount - cost - concession > 0                          |
+-------------------------------------------------------------------------------+
                                      | Passed
                                      v
+-------------------------------------------------------------------------------+
| Gate 3: Model Readiness & Advisory Safety Gate (Phase 5 Boundary)              |
| - Status: BENCHMARK_VALIDATED_AWAITING_PRODUCTION_LOGS                        |
| - Mode: ADVISORY_HUMAN_REVIEW                                                 |
| - Does action require customer contact?                                       |
|     * Yes + Pre-Approved by Operator -> AUTHORIZED                            |
|     * Yes + NOT Pre-Approved        -> PENDING_APPROVAL (Action: NO_ACTION)    |
|     * No (e.g. Gateway Auto-Retry)   -> AUTHORIZED                            |
+-------------------------------------------------------------------------------+
                                      |
                                      v
+-------------------------------------------------------------------------------+
| Gate 4: Conformal Uncertainty Filtering                                       |
| - Rejects high-risk actions when lower bound on uplift <= 0                   |
+-------------------------------------------------------------------------------+
                                      |
                                      v
+-------------------------------------------------------------------------------+
| Output & Ledger: SHA-256 Snapshot Recorded                                    |
| - Immutable ledger record created with snapshot hash                          |
+-------------------------------------------------------------------------------+
```

### Authorization Findings

1. **Autonomous Execution Prevention:** A recommendation from a benchmark model cannot directly cause external customer contact or generate payment links without human intervention. Unapproved requests are routed to `PENDING_APPROVAL`.
2. **Safe Gateway Retries:** Technical gateway retries (`INSTANT_SMART_RETRY`) do not contact customers or grant concessions. When compliant with policy and positive NEV, they can execute autonomously without human review.
3. **Deterministic Immutability:** All decisions produce a deterministic SHA-256 snapshot hash covering input context, candidate scores, policy gate traces, and the supervisor verdict.
